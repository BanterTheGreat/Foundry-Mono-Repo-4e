- Option list warm-up (Android): the Home screen prepares the default Class and Ancestry lists, including ancestry feature details, in the background before character selection. Both are shared with character pickers using the same ordered package configuration. Other supported lists the picker can open through level 20 are checked in the background when a character is opened or created and after each saved edit, with a short settle delay so a burst of edits never queues behind background work. Only lists the character can actually edit are warmed: they come from the engine's active choices, so a Fighter never warms an Avenger's Vindicator's Censure. Lists refresh only when something they depend on changed: the Class and Ancestry pickers never refresh while the character is open; saving a pick keeps that slot's warmed list when its candidate pool and other eligibility inputs are unchanged, and later-level edits keep earlier-level lists; and edits that touch no rules (name, player, notes, gender, age, deity, languages) refresh nothing, while Environment and Upbringing count as level 1 changes. Warm-up is a priority queue of the missing work, rebuilt from the character after each saved edit: every choice still unmade comes first, nearest level first (so a level 4 feat precedes a level 5 daily), and within a level unfilled ancestry power choices (including after an ancestry change), Class Feature choices, power pools, the Class, Ancestry and General feat tabs of unfilled feat slots (including earned advancement feat slots once reached), then any other choices, a reached Paragon Path pick and Theme; next come already-made choices whose pickers the user opened lately (the eight most recent, most recent first), whose rows an edit may have invalidated; last come the remaining made choices, which a loaded character rarely reopens, power pools and class features before feat tabs. Each queued list only does what it still lacks: an already complete list costs one short lock hold, a list rebased onto an edit lists its rows again and checks only the rows without a retained result, and slots the character no longer offers drop out of the queue. An open picker outranks background warming, which checks only a few rows per batch and pauses between batches while any picker is filling or an edit is waiting to save, then resumes from the same list. At most 32 lists are retained, the least recently used going first, and the last tier (made choices) continues existing lists but never creates one once that limit is reached. Class and Ancestry also use the other-choices phase when Home has no matching rows. Theme refreshes when another level 1 decision changes. Utilities the Levels screen does not offer and the target-dependent replacement picker are not warmed. The picker reuses the checked rows, so it opens without the batch-by-batch fill. Lists warmed for one document share a single read session, so the warm-up decodes each content chunk and evaluates the character once rather than once per list (a level 19 character has 12 feat slots); a saved edit starts a new session for the lists it refreshes. Candidate eligibility checks prepare each list's baseline character content once and add only a candidate's own definitions, keep a bounded set of reusable facts for a feat slot's three tabs, and release them once every tab is checked, so a feat list of about 600 rows checks several times faster with identical results. The work shares the picker's browsing snapshot and lock, runs one batch at a time so edits and previews go first, and is cancelled by any later edit, character change or content reload. A missing Class or Ancestry is not an error, and a background read failure is never shown; the picker retries and reports it. Manual check: on a device, wait on Home, open New Character and confirm the Class menu is ready. Select a class and open Ancestry to confirm its choices and features are ready.
