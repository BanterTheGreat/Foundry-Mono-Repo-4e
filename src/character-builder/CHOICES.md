# Character Builder choices

Use the full list with collapsible rows for new Android catalog choices. Class Feature is the reference implementation. Feat uses the same layout. Class and Equipment use sectioned lists. Ancestry and Theme use split readers. Use one of the other layouts only when the choice fits the cases listed below.

Keep tab fields and sheet rows consistent. Use the compact `Field` for saved or empty choices on a tab. The tab label already names the page. In the sheet, reuse `ChoicePickerSheet`, `CollapsibleChoiceList`, compact `ChoiceCard` rows, and `ChoicePickerActions`. These components set the sheet height, gutter, row spacing, folio scrollbar, and footer. Put option details inside the expanded row at compact size. Use `PlainChoiceDescription` for plain text and `ControlledDescription` for authored HTML.

## Picker layouts

| Choice | Default layout |
| --- | --- |
| Class Feature, Feat, and other catalog choices | **Full list with collapsible rows (default).** Use the Class Feature picker in `CatalogChoiceList` as the reference. A new pick expands its card and replaces the draft. Tapping the selected row toggles its detail. |
| Class | **Sectioned list with collapsible rows.** Reuse `ClassPicker` in new character creation and Progression. It groups classes by role, sorts names within each group, and shows fixed-width power-source badges. Revealed ineligible classes stay in their role group. `SectionedChoiceList` accepts ordered sections and caller-supplied rows. |
| Equipment | **Sectioned list with collapsible rows.** Use the Class picker’s `SectionedChoiceList`. Group weapons by authored proficiency tier and armor by Light or Heavy. Show ineligible items in red within their own section and let players inspect them. |
| Power-only catalog, including attack, utility, and power replacement | **Split reader.** Reuse `PowerChoiceReader` and `CatalogReaderPanes`. Put compact rows above an independently scrollable `PowerBlock`. Power search acts on the current pool and matches names and authored rules. Pick the earlier slot before staging a replacement. |
| Ancestry or Theme | **Split reader.** Reuse `AdvancementChoiceReader` and the independently scrolling details pane for flavor, attributes, grants, powers, and choices or modifications where available. |
| Environment or Upbringing | **Full list with collapsible rows.** Show the origin description and offered skills inline. Use `backgroundEdit` to save the origin and clear any stale skill together. |
| Structured values, proficiencies, or ability edits | **Full sheet with direct controls.** Use compact rows for values and skills, and steppers for allocation. The free proficiency editor stages exactly two picks. |

The layouts share a fixed Progression sheet height of 710 dp capped at 91% of window height, with actions below the scrolling content. Use the existing folio scrolling and choice card styles. In a split reader, an explicit row tap can stage a draft. The reading pane follows the inspected row, the visible selected row, or the first visible row in that order. Opening the sheet, searching, and revealing ineligible entries only change what can be read. Reset detail scroll when the inspected entry changes. Start with [ProgressionScreen.kt](android/src/main/kotlin/dev/modern4e/builder/ui/screens/ProgressionScreen.kt) and [ChoiceCard.kt](android/src/main/kotlin/dev/modern4e/builder/ui/components/ChoiceCard.kt).

## Automatic grants and equipment

Levels renders automatic features and powers from the engine at the level they are acquired. Standalone grant cards use the same compact label and value layout as choice fields and expand for reading. A feature authored with `grantDisplay: CHOICE_INTRODUCTION` supplies the picker introduction for its own choices. Use `GRANT_SUMMARY` for a feature whose text only restates grants already shown at that level. Use the default `STANDALONE` whenever the feature has rules of its own, including when it also has choices or grants. Keep editable substitutions in their existing choice rows. At level 0, pair Class with Theme and Environment with Upbringing. Pair Ancestry with Ancestry Language when offered and retain the engine’s acquisition level when saving the language. Show starting ancestry power choices full width immediately below the Ancestry row and keep their existing decision slots. After the level 0 choices, show starting grants in Ancestry, Class, and Theme sections. Include starting ancestry and class features and powers, and starting Theme powers.

Equipment uses the sectioned list for its four optional equipped slots. Its catalog is prepared from Home. Keep all items in their authored categories and use red styling for items the character lacks proficiency to select. Allow Improvised weapons regardless of proficiency. Use the existing shared equipment edits so saving or clearing gear recalculates defenses.

## Choice identity and edits

1. **Find the slot.** Use the reserved creation and advancement slots for baseline choices. For authored choices, use the engine's active `EngineChoice` and its acquisition level through `Progression.levelChoices`. The stable `ChoiceSlotId(sourceInstanceId, choiceId, ordinal)` identifies the occurrence being edited. Reuse the source occurrence ID so its nested choices keep their identity. Automatic grants can supply the displayed value. Authored grant replacements use the engine's offered choice.
2. **Read the offered values.** Entry choices go through `BuilderSession.progressionOptionRows`. Proficiency and structured value choices read the slot's offered skills or values from `state.rules.choices`. Keep choice labels, section placement, and required-choice indicators in the existing Progression helpers.
3. **Stage and save.** Initialize the sheet from the saved choice or displayed grant. Stage a `BuilderEdit` locally and pass it to `BuilderSession.edit` on Save. Cancel discards the draft, and Clear stages a removal where supported. Use `progressionEntryInstance` for early entry edits, typed edits for values/proficiencies/allocation, and `BuilderEdit.Batch` for changes that must succeed together. Through level 2 the shared operations check choices. Later-level entry picks use `LaterDecisions` and show incomplete automation. A progression replacement stores both the prior target slot and the new choice.
4. **Verify the normal entry point.** Open the choice from Levels or its existing caller. Check the saved value on reopen, draft changes on tap, cancellation, and any relevant eligibility, loading, or replacement state. Find the unit suites under [Progressive feat listing and picker tests](../../tests/README.md#progressive-feat-listing).

Use [Progression.kt](android/src/main/kotlin/dev/modern4e/builder/Progression.kt) for slot discovery and labels, [BuilderSession.kt](android/src/main/kotlin/dev/modern4e/builder/BuilderSession.kt) for editing and option loading, and [ENGINE.md](shared/ENGINE.md) for persistence and rules contracts.

## Catalog loading and eligibility

- Load the requested slot and feat tab from catalog metadata before resolving definitions. The Feat picker opens on Class. Class and Ancestry tabs scope indexed entries to the character's applicable access IDs, including multiclass or Past Life qualifications where applicable. Index scope narrows the candidates. Eligibility still comes from the shared choice evaluator.
- Reuse `BuilderOptionListing` for batched checks and `BuilderSession` for cancellation, cache invalidation, and warm-up. Warm-up uses active picker slots and shares its results with the open sheet. Update its targets when a change affects which choices Levels can open.
- Feed the rows to `pickerOptions`. The sheet shows progress until the current list finishes checking. Checked eligible rows appear first. The toggle goes below the eligible rows and reveals ineligible entries and their reasons. Stage an ineligible edit only in pickers that explicitly allow it. Equipment always shows ineligible options for inspection. Search, filters, loading, and unavailable definitions never stage an edit.

See [BuilderOptionListing.kt](shared/src/commonMain/kotlin/dev/modern4e/builder/BuilderOptionListing.kt), [ProgressionOptions.kt](android/src/main/kotlin/dev/modern4e/builder/ProgressionOptions.kt), and [PowerReaderOptions.kt](android/src/main/kotlin/dev/modern4e/builder/PowerReaderOptions.kt).
