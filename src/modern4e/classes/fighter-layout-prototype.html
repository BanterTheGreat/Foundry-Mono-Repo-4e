Two rules pages after the existing illustrated class opener. All three contain the same Fighter mechanics. The bar and these notes are prototype controls, not book content.

What stays consistent across classes

Class header and running footer · proficiency rows with optional implements · six-cell defense/health strip · ability allocation · automatic feature sections · explicit “choose one” groups · power cards with attached follow-ups · compact power directory · optional keyword glossary.

How this becomes Typst

Candidate helpers: classHeader, classProfile, abilityAllocation, featureSection, featureChoice, linkedPowerGroup, powerDirectory. Keep the existing powers.power renderer. These are component boundaries to evaluate, not new production code.

Shared visual grammar, flexible page count: a Wizard spellbook table or long Swordmage Aegis choices can use extra feature pages. Do not force every class into the Fighter’s exact two-page allocation.

Browser font fallbacks and pagination are illustrative. Final approval needs a Typst render with the book’s fonts. Rule labels and ordering are editorial; formulas follow the active helper, including “Healing Surge.”
